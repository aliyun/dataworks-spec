## 简介

dataworks-spec项目提供了一套完整的工具链，用于在不同工作流调度系统之间进行迁移。核心功能包括从源系统导出工作流、转换工作流模型以及导入到目标系统。本指南将帮助新用户快速上手，完成从DolphinScheduler或Airflow到DataWorks的迁移。

## 环境准备

在开始使用dataworks-spec项目之前，需要准备相应的环境变量。这些变量将用于配置源系统和目标系统的连接信息。

对于从DolphinScheduler迁移到DataWorks的场景，需要设置以下环境变量：

```shell
# DolphinScheduler配置变量
export DOLPHINSCHEDULER_API_ENDPOINT=http://server:port
export DOLPHINSCHEDULER_API_TOKEN=从DolphinScheduler获取的md5_token
export DOLPHINSCHEDULER_VERSION=1.3.9
export DOLPHINSCHEDULER_PROJECT_NAME=你的DolphinScheduler项目名称

# 阿里云配置变量
export ALIYUN_ACCESS_KEY_ID=你的访问密钥ID
export ALIYUN_ACCESS_KEY_SECRET=你的访问密钥密钥
export ALIYUN_REGION_ID=cn-shanghai
# 要导入的DataWorks工作空间ID
export ALIYUN_DATAWORKS_WORKSPACE_ID=你的DataWorks工作空间ID
```

这些环境变量将在后续的迁移过程中被自动引用。

## 依赖安装

dataworks-spec项目的依赖管理主要通过Maven和pip两种方式。Java组件使用Maven进行依赖管理，而Python脚本则使用pip。

首先，确保系统中已安装Java 8+和Python 3.8+。然后，安装Python依赖：

```bash
# 进入dwcli目录并安装依赖
cd dwcli
pip install -e .
```

或者使用requirements.txt文件安装：

```bash
pip install -r dwcli/requirements.txt
```

对于Java组件，项目使用Maven进行构建，相关依赖在pom.xml文件中定义。

## 工具设置

dataworks-spec项目包含多个工具组件，需要正确设置才能正常使用。

### MigrationX配置

MigrationX的主要配置文件位于`client/migrationx/src/main/conf/migrationx.json`。该文件定义了读取、转换和写入三个阶段的命令行参数：

```json
{
  "reader": {
    "name": "dolphinscheduler",
    "params": [
      "-a dolphinscheduler",
      "-e ${DOLPHINSCHEDULER_API_ENDPOINT}",
      "-t ${DOLPHINSCHEDULER_API_TOKEN}",
      "-v ${DOLPHINSCHEDULER_VERSION}",
      "-p ${DOLPHINSCHEDULER_PROJECT_NAME}",
      "-f ${PWD}/${DOLPHINSCHEDULER_PROJECT_NAME}.zip"
    ]
  },
  "transformer": {
    "name": "dolphinscheduler_to_dataworks",
    "params": [
      "-a dolphinscheduler_to_dataworks",
      "-c ${MIGRATIONX_HOME}/conf/dataworks-transformer-config.json",
      "-s ${PWD}/${DOLPHINSCHEDULER_PROJECT_NAME}.zip",
      "-t ${PWD}/${DOLPHINSCHEDULER_PROJECT_NAME}_dw.zip"
    ]
  },
  "writer": {
    "name": "dataworks",
    "params": [
      "-a dataworks",
      "-e dataworks.${ALIYUN_REGION_ID}.aliyuncs.com",
      "-i ${ALIYUN_ACCESS_KEY_ID}",
      "-k ${ALIYUN_ACCESS_KEY_SECRET}",
      "-p ${ALIYUN_DATAWORKS_WORKSPACE_ID}",
      "-r ${ALIYUN_REGION_ID}",
      "-f ${PWD}/${DOLPHINSCHEDULER_PROJECT_NAME}_dw.zip",
      "-t SPEC"
    ]
  }
}
```

此配置文件默认情况下无需修改，MigrationX会按照此配置依次执行读取、转换和写入操作。

## 基本使用示例

本节将演示如何使用MigrationX工具完成从源系统导出工作流、转换工作流模型并导入到目标系统的完整流程。

### 执行迁移

设置好环境变量和配置文件后，可以通过以下命令启动迁移：

```shell
bin/migrationx.py
```

这个脚本会自动执行以下三个步骤：

1. **读取阶段**：从DolphinScheduler读取指定项目的工作流配置，生成一个zip文件
2. **转换阶段**：将zip文件转换为DataWorks工作流格式的zip文件
3. **写入阶段**：将转换后的DataWorks工作流zip文件导入到指定的DataWorks工作空间

整个过程是自动化的，MigrationX会依次执行配置文件中定义的各个步骤。

**Section sources**
- [client/migrationx/src/main/bin/migrationx.py](file://client/migrationx/src/main/bin/migrationx.py#L1-L44)

### 读取工作流

除了通过migrationx.py一键执行外，也可以单独使用reader工具从源系统读取工作流：

```shell
# 从DolphinScheduler读取
bin/reader.py \
-a dolphinscheduler \
-e http://dolphinscheduler_api_host \
-t {token} \
-v 1.3.9 \
-p project_a \
-f project_a.zip

# 从Airflow读取
bin/reader.py \
-a airflow \
-d /path/to/dag_folder \
-o output.json

# 从阿里云EMR读取
bin/reader.py \
-a aliyunemr \
-d ./target/dump \
-e emr.aliyuncs.com \
-i ${accessId} \
-k ${accessKey} \
-r ${regionId} \
-p emr_prj01,emr_prj02
```

### 转换工作流

使用transformer工具将一种调度系统的工作流导出包转换为另一种调度系统的工作流包：

```shell
bin/transformer.py \
-a dolphinscheduler_to_dataworks \
-c dataworks-transformer-config.json \
-s project_a.zip \
-t dw.zip
```

转换配置文件可以定义节点类型的映射关系，例如：

```json
{
  "format": "SPEC",
  "locale": "zh_CN",
  "settings": {
    "workflow.converter.shellNodeType": "EMR_SHELL",
    "workflow.converter.commandSqlAs": "EMR_HIVE",
    "workflow.converter.sparkSubmitAs": "EMR_SPARK",
    "workflow.converter.target.unknownNodeTypeAs": "DIDE_SHELL",
    "workflow.converter.mrNodeType": "EMR_MR",
    "workflow.converter.target.engine.type": "EMR",
    "workflow.converter.dolphinscheduler.sqlNodeTypeMapping": {
      "POSTGRESQL": "EMR_HIVE",
      "MYSQL": "EMR_HIVE",
      "HIVE": "EMR_HIVE"
    }
  }
}
```

使用writer工具将工作流配置写入目标系统：

## dwcli命令行工具操作

dwcli是一个强大的DataWorks CLI工具，支持配置即代码（CaC）管理。

### 安装dwcli

```bash
pip install -e .
```

### 基本操作

```bash
# 创建新节点
dwcli node create ./tasks --name my-daily-task --template odps-sql-daily

# 设置配置
dwcli node set ./tasks/my-daily-task spec.timeout=3600 --type int

# 查看配置
dwcli node inspect ./tasks/my-daily-task spec.timeout

# 编辑代码
dwcli node code edit ./tasks/my-daily-task

# 验证配置
dwcli node validate ./tasks/my-daily-task
```

### 模板管理

dwcli使用Jinja2模板来生成工作流配置。例如，手动工作流模板如下：

```json
{
  "spec": {
    "version": "1.0",
    "kind": "ManualWorkflow",
    "metadata": {
      "name": "{{ name }}",
      "owner": "{{ owner | default('admin') }}"
    },
    "spec": {
      "nodes": [
        {
          "id": "{{ name }}",
          "name": "{{ name }}",
          "type": "SHELL",
          "script": {
            "path": "{{ name }}.sh"
          }
        }
      ],
      "flow": []
    }
  },
  "code": {
    "extension": "sh",
    "content": "#!/bin/bash\n# Manual workflow script for {{ name }}\n\necho \"Executing {{ name }}\"\n"
  }
}
```

## 常见用户场景

### 从DolphinScheduler迁移到DataWorks

这是最常见的迁移场景，步骤如下：

1. 设置DolphinScheduler和DataWorks的环境变量
2. 验证migrationx.json配置文件
3. 执行migrationx.py脚本启动迁移

### 从Airflow迁移到DataWorks

对于Airflow用户，可以使用专门的转换器：

```shell
# 读取Airflow DAG
bin/reader.py -a airflow -d /path/to/dags -o airflow_output.json

# 转换为DataWorks格式
bin/transformer.py -a airflowv2_to_dataworks -s airflow_output.json -t dataworks_output.zip

# 导入到DataWorks
bin/writer.py -a dataworks -f dataworks_output.zip [其他参数]
```

## 故障排除

### 常见问题

1. **环境变量未设置**：确保所有必要的环境变量都已正确设置
2. **网络连接问题**：检查源系统和目标系统的网络连接是否正常
3. **权限不足**：确保API Token和Access Key具有足够的权限
4. **版本不兼容**：确认源系统版本与MigrationX支持的版本匹配

### 调试方法

可以通过单独执行各个组件来定位问题：

```shell
# 只执行读取阶段
python bin/reader.py [参数]

# 只执行转换阶段
python bin/transformer.py [参数]

# 只执行写入阶段
python bin/writer.py [参数]
```

这样可以逐个排查每个阶段的问题。
