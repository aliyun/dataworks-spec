## 参数配置概述

dataworks-spec项目提供了一套完整的参数配置系统，用于在工作流中定义和管理各种类型的参数。该系统支持全局参数、节点参数和环境变量的配置，通过灵活的作用域机制和参数传递方式，实现了复杂工作流场景下的参数管理需求。参数配置系统基于JSON Schema定义了严格的参数结构，确保了参数定义的规范性和可验证性。

## 参数类型与作用域

### 变量作用域类型

dataworks-spec项目定义了多种变量作用域，通过`VariableScopeType`枚举类实现，每种作用域决定了参数的可见性和生命周期。

```mermaid
classDiagram
class VariableScopeType {
+TENANT("Tenant")
+WORKSPACE("Workspace")
+FLOW("Workflow")
+NODE_PARAMETER("NodeParameter")
+NODE_CONTEXT("NodeContext")
}
VariableScopeType : String getLabel()
```

**Diagram sources**
- [VariableScopeType.java](file://spec/src/main/java/com/aliyun/dataworks/common/spec/domain/enums/VariableScopeType.java)

#### 作用域级别说明

- **租户级(TENANT)**：在整个租户范围内可见，适用于跨工作空间共享的全局配置
- **工作空间级(WORKSPACE)**：在特定工作空间内可见，适用于工作空间级别的共享配置
- **工作流级(FLOW)**：在单个工作流内可见，适用于工作流级别的参数共享
- **节点参数级(NODE_PARAMETER)**：作为节点的输入参数，用于接收外部传入的参数值
- **节点上下文级(NODE_CONTEXT)**：在节点执行过程中生成或定义的参数，可用于后续节点的输入

### 参数类型

参数类型通过`VariableType`枚举类定义，支持多种参数类型以满足不同的使用场景。

```mermaid
classDiagram
class VariableType {
+NO_KV_PAIR_EXPRESSION("NoKvVariableExpression")
+SYSTEM("System")
+CONSTANT("Constant")
+NODE_OUTPUT("NodeOutput")
+PAI_OUTPUT("PaiOutput")
+PASS_THROUGH("PassThrough")
}
VariableType : String getLabel()
```

**Diagram sources**
- [VariableType.java](file://spec/src/main/java/com/aliyun/dataworks/common/spec/domain/enums/VariableType.java)

#### 参数类型说明

- **NO_KV_PAIR_EXPRESSION**：非键值对表达式，兼容旧版参数格式
- **SYSTEM**：系统变量，如`${yyyymmdd}`等内置时间变量
- **CONSTANT**：常量，固定不变的参数值
- **NODE_OUTPUT**：节点输出变量，由前序节点执行后输出的参数
- **PAI_OUTPUT**：PAI组件输出变量，特定于PAI组件的输出参数
- **PASS_THROUGH**：透传变量，用于将前序节点的输出直接传递给后续节点

## 参数定义与使用

### 全局参数配置

全局参数在工作流级别定义，可在整个工作流中使用。通过`variables`字段在工作流规范中定义全局参数。

```mermaid
flowchart TD
Start([工作流定义]) --> DefineVariables["定义variables数组"]
DefineVariables --> AddVariable["添加参数对象"]
AddVariable --> SetName["设置name属性"]
AddVariable --> SetScope["设置scope属性"]
AddVariable --> SetType["设置type属性"]
AddVariable --> SetValue["设置value属性"]
SetValue --> End([完成参数定义])
```

## 参数传递机制

### 静态参数传递

静态参数在工作流定义时就已经确定，通过常量或系统变量的形式传递。

```mermaid
sequenceDiagram
participant Workflow as "工作流定义"
participant Parser as "参数解析器"
participant Node as "执行节点"
Workflow->>Parser : 定义常量参数
Parser->>Parser : 解析参数值
Parser->>Node : 传递解析后的参数
Node->>Node : 使用参数执行任务
```

**Diagram sources**
- [SpecVariableParser.java](file://spec/src/main/java/com/aliyun/dataworks/common/spec/parser/impl/SpecVariableParser.java)

### 动态参数传递

动态参数在工作流执行过程中生成，通过节点输出变量的形式在节点间传递。

```mermaid
sequenceDiagram
participant NodeA as "节点A"
participant Context as "执行上下文"
participant NodeB as "节点B"
NodeA->>Context : 输出变量到上下文
Context->>Context : 存储变量值
Context->>NodeB : 为节点B提供输入变量
NodeB->>NodeB : 使用输入变量执行
```

**Diagram sources**
- [VariableUtils.java](file://spec/src/main/java/com/aliyun/dataworks/common/spec/utils/VariableUtils.java)

### 运行时参数传递

运行时参数在节点执行时动态计算，支持复杂的参数表达式和函数调用。

```mermaid
flowchart TD
Start([节点执行]) --> EvaluateExpression["评估参数表达式"]
EvaluateExpression --> CheckSystemVar{"系统变量?"}
CheckSystemVar --> |是| ResolveSystemVar["解析系统变量"]
CheckSystemVar --> |否| CheckFunction{"函数调用?"}
CheckFunction --> |是| ExecuteFunction["执行函数"]
CheckFunction --> |否| UseLiteral["使用字面值"]
ResolveSystemVar --> End([使用计算结果])
ExecuteFunction --> End
UseLiteral --> End
```

## 复杂参数场景示例

### 参数枢纽配置示例

参数枢纽（Param Hub）用于集中管理节点的输入输出参数，支持复杂的参数依赖关系。

```json
{
  "version": "1.0.0",
  "kind": "CycleWorkflow",
  "nodes": [
    {
      "id": "param_1",
      "param-hub": {
        "variables": [
          {
            "name": "my_const",
            "type": "Constant",
            "scope": "NodeContext",
            "value": "cn-shanghai"
          },
          {
            "name": "my_var",
            "type": "System",
            "scope": "NodeContext",
            "value": "${yyyymmdd}"
          },
          {
            "name": "outputs",
            "type": "PassThrough",
            "scope": "NodeContext",
            "referenceVariable": {
              "name": "outputs",
              "type": "NodeOutput",
              "scope": "NodeContext",
              "value": "${outputs}",
              "node": {
                "output": "autotest.28517448_out"
              }
            }
          }
        ]
      }
    }
  ]
}
```

## 最佳实践

### 参数命名规范

遵循统一的参数命名规范，提高参数的可读性和可维护性。

```mermaid
flowchart TD
NamingRule["参数命名规则"] --> Prefix["前缀标识"]
NamingRule --> Separator["分隔符"]
NamingRule --> Descriptive["描述性名称"]
NamingRule --> Suffix["后缀标识(可选)"]
Prefix --> |示例| P["p_ (参数)"]
Prefix --> |示例| C["c_ (常量)"]
Prefix --> |示例| S["s_ (系统)"]
Separator --> |推荐| Underscore["_"]
Descriptive --> |要求| Meaningful["有意义的描述"]
Suffix --> |示例| Date["_date"]
Suffix --> |示例| Time["_time"]
```

### 参数作用域选择

根据参数的使用范围选择合适的作用域，避免作用域过大或过小。

```mermaid
decisionDiagram
Start{参数使用范围}
Start -->|整个租户| TENANT["选择TENANT作用域"]
Start -->|整个工作空间| WORKSPACE["选择WORKSPACE作用域"]
Start -->|单个工作流| FLOW["选择FLOW作用域"]
Start -->|节点输入| NODE_PARAMETER["选择NODE_PARAMETER作用域"]
Start -->|节点内部| NODE_CONTEXT["选择NODE_CONTEXT作用域"]
```

### 参数安全性考虑

敏感参数应进行加密处理，避免明文存储。

```mermaid
flowchart TD
SecureParam["安全参数处理"] --> Identify["识别敏感参数"]
Identify --> Encrypt["加密存储"]
Encrypt --> Store["安全存储"]
Store --> Decrypt["运行时解密"]
Decrypt --> Use["使用参数"]
Use --> Cleanup["使用后清理"]
```
